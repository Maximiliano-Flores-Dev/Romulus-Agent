El Agent Core es el corazón de Romulus Agent. Coordina el loop de razonamiento, gestiona los turnos con el modelo, comprime trayectorias largas y alimenta el ciclo de aprendizaje que genera nuevas skills. En esta página verás cómo procesa un turno y cómo aprende.

<CardGroup cols={2}>

## Anatomía de un turno

<Steps>
  <Step title="Recuperar contexto">
    El core lee la sesión activa desde el estado persistente y arma el prompt con el historial cacheado.
  </Step>
  <Step title="Enviar toolset completo">
    Cada request al proveedor de modelo incluye todos los tools activos. Esto permite que el modelo elija con contexto completo.
  </Step>
  <Step title="Decisión del modelo">
    El modelo devuelve texto, una llamada a tool o ambos. El core interpreta la respuesta.
  </Step>
  <Step title="Ejecución con permisos">
    Si el modelo invoca una tool, el runtime valida los permisos antes de ejecutarla.
  </Step>
  <Step title="Persistir y comprimir">
    El resultado se guarda en la trayectoria. Si el contexto supera el umbral, se comprime automáticamente.
  </Step>
  <Step title="Continuar o cerrar">
    Si el modelo pidió otro turno, el loop repite. El límite por defecto es `max_turns: 150`.
  </Step>
</Steps>

## Ciclo de aprendizaje

Romulus cierra el bucle entre ejecución y mejora. Cada trayectoria alimenta la generación de skills reutilizables.

```text
Task Execution
    ↓
Trajectory Logging
    ↓
Post-Task Evaluation
    ↓
Skill Creation (si se detecta patrón)
    ↓
Skill Refinement (mejora en cada reutilización)
    ↓
Next Session (skills disponibles)
```

## Compresión de contexto

Las conversaciones largas pueden superar el límite del modelo. Romulus aplica compresión cuando el contexto alcanza la mitad del máximo disponible, preservando los prefijos cacheados para no invalidar el prompt cache.

<Tip>
  Ajusta `compression.threshold` en tu configuración para intercambiar coste y contexto disponible.
</Tip>

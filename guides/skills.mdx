Romulus Agent aprende de cada interacción para crear skills reutilizables que mejoran su eficiencia en tareas repetitivas. En esta guía verás cómo funciona el ciclo de aprendizaje, dónde viven las skills y qué precauciones tomar para no romper el prompt cache.

## El ciclo de aprendizaje

<Steps>
  <Step title="Task execution">
    El agente ejecuta una tarea usando el toolset del core. Cada llamada al modelo incluye la lista completa de tools.
  </Step>
  <Step title="Trajectory logging">
    La secuencia de prompts, tool calls y resultados se persiste en SQLite (WAL + FTS5). Esta trayectoria es la materia prima del aprendizaje.
  </Step>
  <Step title="Post-task evaluation">
    Al terminar la tarea, el agente evalúa el resultado, identifica pasos redundantes y detecta patrones.
  </Step>
  <Step title="Skill creation">
    Si el patrón es generalizable, Romulus crea una skill que encapsula el flujo aprendido.
  </Step>
  <Step title="Skill refinement">
    Cada reutilización refina la skill: se acortan pasos, se ajustan parámetros, se mejora la fiabilidad.
  </Step>
</Steps>

## Estructura de directorios

| Directorio | Contenido |
| --- | --- |
| `skills/` | Skills activas cargadas automáticamente en cada sesión. |
| `optional-skills/` | Skills disponibles pero desactivadas. Se cargan bajo demanda. |

Puedes mover skills entre directorios para activarlas o desactivarlas sin borrarlas. Los archivos son legibles y versionables con Git.

Antes de crear una skill nueva, sigue la jerarquía del proyecto. Añadir capacidades al core es el último recurso.

## Preservar el prompt cache

<Warning>
  Las skills nunca deben mutar el system prompt ni cambiar el toolset activo durante una sesión. Cualquier mutación invalida el prompt cache y aumenta latencia y coste en cada turno posterior.
</Warning>

Si una skill necesita un tool distinto, cierra la sesión, ajusta el toolset con `hermes tools` y vuelve a arrancar con `hermes --now`.
